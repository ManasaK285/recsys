Phase 3Live FDE Case Study: The 15-Minute Cloud Run Timeout

No HireInfrastructure Diagnostics & System Triage

Prompt: A production Cloud Run LangGraph service throws intermittent 504 gateway timeouts precisely every 15 minutes under heavy load. The client blames API rate limits.

Investigation & Resolution Playbook

  1. Root Cause Identification: Predictable 15-minute intervals under load point directly to Cloud Run CPU throttling or background task execution limits. When requests complete, default Cloud Run instances throttle CPU until a new request arrives. If async persistence or telemetry tasks attempt to run post-response, the container freezes or terminates.
  2. Verification Strategy: Inspect Cloud Run instance revision settings and review Cloud Logging for SIGTERM/SIGKILL exit codes matching memory or thread exhaustion timelines.
  3. Permanent Fix: Reconfigure Cloud Run deployment flags to keep CPU allocated at all times: gcloud run services update [SERVICE_NAME] --no-cpu-throttling
What went wrong in the round
  • Guessed "rate limiter" and suggested tweaking arbitrary rate limit values.
  • Failed to systematically investigate container lifecycle rules and CPU allocation models.
