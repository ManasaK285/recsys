# ReasonLens — Privacy Notes

## What is collected

| Data | Collected? | Notes |
|---|---|---|
| Actual GPS coordinates | **Never** | The app never calls a location API to read a coordinate; it only records which OS-level permission the participant granted. |
| Permission decision (granted/denied) | Yes | Core dependent variable. |
| Precision level (approximate/precise) | Yes, if granted | Core dependent variable. |
| Response time | Yes | Milliseconds between reason text shown and OS dialog result. |
| Survey Likert responses (4 items) | Yes | 1-5 scale, no free text. |
| Participant identifier | Yes, anonymous | Client-generated UUID, stored only in local SharedPreferences and attached to server rows; not linked to any account, device ID, or advertising ID. |
| Demographic group | Optional | Free-form bucket string set by the researcher's recruitment process, not entered by the participant in-app in this build. |

## What is *not* collected

- Real GPS/location coordinates, at any precision.
- Contacts, photos, device identifiers, advertising ID, IP-based
  geolocation, or any other runtime permission beyond location.
- Any free-text input from the participant.

## Data flow

Android app → HTTPS → FastAPI backend → SQLite (dev) or PostgreSQL
(production) → analysis/ML pipeline (reads DB exports, never phones
home). The Streamlit dashboard reads only local files
(`data/results/results.json`, `data/processed/tidy.csv`) generated by
the pipeline — it does not query the live database directly.

## Simulation vs. pilot separation

Every participant row is tagged `mode = "simulation"` or `mode =
"pilot"` at write time (`backend/app/models.py::Participant.mode`).
Simulated data is generated entirely offline by
`experiments/simulation.py` and is never uploaded to, or intermixed
with, the pilot database.

## Retention and withdrawal

Because participant IDs are anonymous and client-generated, the
research team cannot proactively identify which server-side rows
belong to a participant who wishes to withdraw after the fact, unless
that participant retains and shares their local ID. Consent text should
disclose this limitation explicitly (see `docs/EXPERIMENT_PROTOCOL.md`,
"Withdrawal"). Institutions running a real pilot should also apply
their own IRB-mandated retention schedule to the production database.

## Production hardening checklist (not yet implemented in this repo)

- Enforce HTTPS/TLS termination in front of FastAPI.
- Add rate limiting per participant_id on write endpoints.
- Rotate the experiment `seed` only between pre-registered experiment
  phases, never mid-study, to preserve reproducible randomization.
- Add row-level encryption at rest if hosting PII beyond what's
  described above.
