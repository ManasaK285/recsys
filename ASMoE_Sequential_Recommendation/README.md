# ASMoE Sequential Recommendation

An interactive, ASMoE-inspired next-item recommendation demo using synthetic sequential interactions. The project compares a popularity baseline, SASRec, and two ASMoE variants, and provides a Streamlit interface for exploring recommendations and expert routing.

> **Data note:** The bundled experiment uses synthetic data. Reported metrics demonstrate this experiment only and must not be interpreted as real-world recommendation performance.

## Features

- Synthetic sequential-interaction data generation.
- Temporal train/validation/test splitting and evaluation with previously seen items excluded from recommendation candidates.
- Baselines: Popularity and SASRec.
- ASMoE Stage 1 and Stage 2 models.
- Stage-2 checkpoint loading for interactive recommendations.
- Streamlit dashboard featuring:
  - User selection and recent interaction history.
  - Top-10 unseen-item recommendations with ranking scores.
  - Expert-routing probabilities and selected experts.
  - Saved model-comparison metrics.
  - CSV export of recommendations.
- Configurable experiment settings in `configs/default.yaml`.

## Run the dashboard

Run these commands from the project root—the folder containing `app.py`, `src/`, and `configs/`.

```powershell
python -m streamlit run app.py
```

Streamlit will print a local URL, typically `http://localhost:8501`, that you can open in your browser.

### Dashboard contents

**Recent interaction history**  
Shows the selected user's recent training interactions, including generated item labels and category IDs.

**Top recommendations**  
Displays the highest-scoring candidate items after filtering out items in the selected user's displayed training history. The ranking score is a model score, not a probability.

**Expert routing**  
Displays the model's router probabilities and selected top-k experts when the model exposes router information.

**Model evaluation comparison**  
Loads metrics from `outputs_v2/comparison.csv`, when that file exists. If the file is missing, run the training/evaluation pipeline first.

**Synthetic item labels**  
The synthetic dataset does not provide real product names. Labels such as `Demo item 187 · Category 4` are generated for readability and do not represent real catalog items.


### Full configured run

```powershell
python -m src.train --config configs/default.yaml --output outputs_v2
```

The full run may take a while on CPU. It can generate checkpoints and evaluation artifacts in `outputs_v2/`, including the Stage-2 checkpoint and model-comparison CSV, depending on the training script version.

**Important:** Training with `--output outputs_v2` may overwrite files in that output directory. Back up any checkpoints or results you want to keep before rerunning training.

## Troubleshooting

### `KeyError: 'item_idx_to_raw'`

Some versions of the data pipeline do not return an `item_idx_to_raw` mapping. The dashboard should use the fields that `encode_and_split()` actually returns. The current fixed dashboard uses generated display labels and does not require `data["item_idx_to_raw"]`.

### Stage-2 checkpoint not found

Confirm this file exists relative to the project root:

```text
outputs_v2/best_asmoe_stage2.pt
```

Run Streamlit from the project root:

```powershell
python -m streamlit run app.py
```

If the checkpoint was generated by a different model architecture or incompatible configuration, train a compatible checkpoint using the current source code.

### `streamlit` is not recognized

Use Python's module launcher:

```powershell
python -m pip install streamlit
python -m streamlit run app.py
```

### Evaluation comparison is missing

The dashboard reads:

```text
outputs_v2/comparison.csv
```

Run the training/evaluation command and verify that the CSV exists in the same project folder as `app.py`.

### Charts or tables appear blank

- Refresh the Streamlit page.
- Check the PowerShell terminal for exceptions.
- Confirm that `outputs_v2/comparison.csv` contains rows and numeric metric columns.
- Confirm that the installed Streamlit and pandas versions satisfy `requirements.txt`.
- Restart the app after replacing `app.py`:

```powershell
Ctrl+C
python -m streamlit run app.py
```

## Interpreting results responsibly

- **Recall@K** measures whether the held-out target item appears among the top K recommendations.
- **NDCG@K** accounts for the target item's rank, rewarding higher positions.
- **MRR** rewards placing the target item near the top of the ranking.
- **Router probabilities** indicate the router's weights over experts; they are not recommendation confidence scores.
- A difference between Stage 1 and Stage 2 on one metric does not imply that Stage 2 is better on every metric.
- Synthetic-data results are useful for testing the pipeline and demonstrating the workflow, but do not establish real-world recommendation quality.

## Reproducibility notes

- Experiment settings are read from `configs/default.yaml` or `configs/smoke.yaml`.
- The dashboard regenerates synthetic data from the configured seed, so the generated dataset and user histories depend on the configuration and implementation.
- Keep the configuration and checkpoint from the same experiment together. If the synthetic-data generation logic, item mapping, or model architecture changes, retrain and reevaluate for a consistent result.

## Suggested next steps
